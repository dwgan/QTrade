# 日度流水线与本地看板

本阶段把数据更新、分析、观察和展示串成一条可重复运行的收盘后流水线。

## 1. 完整运行

```powershell
qtrade pipeline daily --date 2026-07-24
```

默认依次执行：

1. 更新 `config.update.datasets` 中配置的日度数据；
2. 生成市场状态报告；
3. 生成行业与风格报告；
4. 生成多因子排名和候选；
5. 生成候选变化、自选股与影子组合日报；
6. 生成本地只读 HTML 看板。

季度财务指标不会在日度流水线中反复下载。运行因子分析前，仍需按财报披露节奏使用
`qtrade data financials` 准备历史财务快照。

## 2. 使用已有数据重跑

调试分析逻辑或已经完成数据更新时，可以避免再次访问数据供应商：

```powershell
qtrade pipeline daily --date 2026-07-24 --skip-data
```

也可以覆盖本次更新的数据集：

```powershell
qtrade pipeline daily `
  --date 2026-07-24 `
  --datasets daily_prices,adjust_factors,index_daily,daily_basic,stock_limit
```

`--skip-data` 只跳过供应商访问，不放宽后续模块对历史数据和财务快照的要求。

## 3. 失败与依赖关系

流水线采用以下规则：

- 数据更新失败后，市场、行业和因子分析全部跳过；
- 市场和行业分析互不依赖，其中一个失败不会阻止另一个已经开始的步骤；
- 观察日报只在因子分析成功后运行；
- 看板总会尽量生成，用于展示成功产物和流水线错误；
- 任一步骤失败时命令返回非零退出码。

每次运行都会写入：

```text
reports/pipeline/YYYY-MM-DD/
  run.json
  run.md
```

清单记录每一步的 `completed`、`failed` 或 `skipped` 状态、错误信息和产物路径，适合作为
定时任务的审计入口。

## 4. 本地只读看板

也可以只从已有报告重新生成看板：

```powershell
qtrade dashboard build --date 2026-07-24
```

输出文件：

```text
reports/dashboard/2026-07-24/index.html
```

它是一个无外部资源、无后端服务、无写入操作的静态 HTML 文件，可以直接使用浏览器
打开。看板展示：

- 市场状态、温度、趋势、宽度和风险；
- 行业强弱前十；
- 多因子候选前二十；
- 候选进出和影子组合摘要；
- 本次流水线步骤状态。

所有来自报告的文本都会经过 HTML 转义。若流水线清单显示某一步失败，看板不会读取同一
日期可能残留的旧产物，避免把上一次成功结果冒充为本次结果。

## 5. 自动运行建议

正式设置定时任务前，先连续手工运行并确认：

- 数据供应商权限和调用额度稳定；
- 财务快照按披露周期更新；
- 非交易日由外部调度器跳过，或接受流水线明确失败；
- 进程退出码和 `run.json` 被监控；
- `reports` 与 `data` 定期备份。

当前流水线不会自动发送通知，也不会自动打开浏览器，更不会连接券商或执行交易。
