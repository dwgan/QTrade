# 期货阶段 3 逐日盯市账本

## 1. 当前范围

阶段 3 工程实现已经完成，当前包括实际合约账户账本、数据就绪门禁、保守日线成交器、
换月和减仓订单生命周期、组合级日度编排，以及不可变回测服务。不生成策略信号，不在
真实历史数据门禁失败时发布收益，也不使用连续研究价格成交。

已实现：

- 实际合约多头和空头持仓；
- 整手开仓、部分平仓和全部平仓；
- 合约乘数参与的逐日盯市；
- 成交费用、平仓盈亏和结算盈亏的现金流水；
- 当前保证金、压力保证金、可用资金和追保状态；
- 成交与结算日期严格递增，已结算日期不能被后续事件改写；
- 回测前逐合约、逐日期检查行情、保证金、涨跌停和乘数；
- 缺失数据和重复主键显式阻断，禁止静默代理；
- `T` 日订单最早在预先确定的 `T+1` 交易日尝试成交；
- 买入向上、卖出向下按最小变动价位叠加滑点，并受当日涨跌停限制；
- 缺行情、缺开盘、无成交、异常日内价格和不利方向锁板时保留待成交订单；
- 逐订单记录首次尝试日、尝试次数、最近阻断原因和最终成交日；
- 按手数和名义金额计算通用费用，开仓前检查当日保证金和可用资金；
- 非有限价格、费率、资金和账户参数在进入账本前被拒绝；
- 从目标手数生成增仓、减仓或先平后开的实际合约订单；
- 开仓、通用平仓、平今和平昨使用独立费率规则；
- 换月严格先平旧合约再开新合约，两条腿独立计算滑点和费用；
- 旧腿受阻时新腿不尝试，新腿受阻时保留空仓中间态并跨日重试；
- 按预注册顺序和逐手保证金释放量生成最少整手强制减仓单；
- 日度编排按开盘成交、日终结算、当日信号生成 `T+1` 订单的顺序运行；
- 强平单优先于普通调仓和换月，强平交易日禁止重新增加风险；
- 日终追保自动使用当日结算和方向保证金生成下一交易日减仓单；
- 普通待单或换月未完成时抑制新信号，防止叠加重复订单；
- 所有当前持仓和计划开仓在成交前检查当日结算与方向保证金；
- 滑点 tick、追保缓冲和压力保证金倍率均由独立期货配置控制；
- 回测输入必须引用通过质量检查的阶段 2 `research_build_id`；
- 目标和换月新合约必须匹配阶段 2 在 `T+1` 的时点一致主力合约；
- 输入快照、阶段 2 manifest、换月表和执行配置共同生成内容寻址构建 ID；
- 输出订单、成交尝试、账本、逐日持仓、账户和问题六类不可变 Parquet；
- 同一输入重复构建直接复用，输入内容变化产生新构建；
- `qtrade futures backtest --input <冻结输入.json>` 提供阶段 3 CLI。

真实验收阻断：

- 当前供应商不提供可用的历史 `futures_limits`，无法满足逐合约、逐日涨跌停门禁；
- 结算参数覆盖晚于行情的日期仍可能缺失，必须逐日检查；
- 因此只能完成合成夹具工程验收，禁止发布真实历史收益。

## 2. 账本公式

持仓日终盈亏：

```text
方向 × 手数 × 合约乘数 ×（当日结算价 - 结算基准价）
```

新开仓的首个结算基准是实际成交价，后续交易日基准是上一日结算价。部分平仓先按实际
平仓价相对当前结算基准确认盈亏，剩余手数再按当日结算价盯市，避免重复计算。

账户关系：

```text
期末权益 = 初始权益 + 累计平仓/结算盈亏 - 累计费用
当前保证金 = Σ（手数 × 结算价 × 合约乘数 × 当日保证金率）
可用资金 = 期末权益 - 当前保证金
压力保证金 = 当前保证金 × 压力倍数
```

期货开仓不扣除名义本金。保证金只冻结可用资金，成交费用和盯市盈亏才改变账户权益。

## 3. 数据门禁

每个计划成交的实际合约与交易日必须具备：

1. 正数合约乘数；
2. 正数开盘价、结算价和成交量；
3. 与多空方向对应的正数历史保证金率；
4. 正数且上限高于下限的历史涨跌停价；
5. 唯一的合约与交易日主键。

门禁不会用当前合约规则、固定比例或另一日期的数据填补历史缺口。当前供应商不支持
`ft_limit`，因此真实阶段 3 回测仍会被 `missing_price_limits` 阻断；这属于预期安全行为。

## 4. 手工验收

自动化夹具逐日核对：

- 两手多头开仓、连续两日结算、部分平仓和剩余持仓结算；
- 三手空头在结算价下跌时产生正盈亏；
- 费用、每日盈亏、保证金、压力保证金和可用资金；
- 账本现金流水合计与账户权益完全勾稽；
- 缺失保证金或结算价时账户状态不发生部分修改；
- 超量平仓、反向直接开仓和历史日期回写被拒绝；
- 行情、保证金和涨跌停缺失分别产生独立阻断原因；
- 同日信号不能成交，次日成交价包含方向不利滑点和费用；
- 缺开盘、无成交或锁板订单保留到后续交易日重试；
- 订单尝试日期严格递增，成交订单不能重复执行；
- 开仓保证金不足被拒绝，平仓不额外冻结保证金；
- 只有成功生成的成交记录才写入账本并参与当日结算；
- 旧腿锁板时新腿零尝试，旧腿成交后新腿锁板时账户保持零敞口；
- 新腿在后续交易日恢复成交，旧腿不会重复执行；
- 反向目标先全平原方向，再按目标手数开新方向；
- 强平规划严格按预注册顺序生成足以释放保证金的最少整手订单；
- 非有限开仓资金在旧腿成交前原子拒绝；
- 开仓后价格下跌触发追保，下一日强平优先且被锁普通订单零尝试；
- 两个品种连续完成三次换月，最终持仓只包含目标实际合约；
- 缺少计划开仓合约结算时在任何成交和结算前原子拒绝；
- 同日目标与换月涉及同一合约时在修改账户前拒绝；
- 相同冻结输入重复构建复用同一构建 ID；
- 输入目标手数变化产生新构建 ID；
- 目标合约偏离阶段 2 时点一致换月表时不创建任何回测产物。

## 5. 冻结输入约束

阶段 3 CLI 只接受显式冻结的 JSON 输入。输入至少包含：

1. `research_build_id` 和初始权益；
2. 每个交易日及其下一交易日；
3. 实际合约 OHLC、成交量、涨跌停、结算价和多空保证金率；
4. 带 `product_code` 的目标实际合约与目标手数；
5. 换月两条腿、差异费用和强平候选顺序。

输入目标来自后续策略阶段，但阶段 3 不负责从品种池推导方向或手数。该边界防止把策略
逻辑、参数选择或事后目标偷偷混入成交内核。
