# 期货阶段 0 数据可行性审计

## 1. 结论

阶段 0 的自动化审计能力已经完成。基于 2026-07-24 的真实数据验证：

- 六个期货市场的合约资料、日线行情和每日结算参数均可取得；
- 全市场主力合约映射可取得；
- 当前网关不识别官方 `ft_limit` 涨跌停接口；
- 阶段 1“期货数据底座”可以开始；
- 阶段 3“期货回测内核”暂不满足开工验收，必须先补齐历史涨跌停价。

这里使用两道独立门禁，避免把“可延后处理的回测约束”误判为“全部期货数据不可用”，
同时也避免在缺少涨跌停数据时误称回测已经可靠。

## 2. 使用方法

先在用户环境变量中配置 `TUSHARE_TOKEN` 和 `TUSHARE_API_URL`，然后执行：

```powershell
.\.venv\Scripts\python.exe -m qtrade futures audit --date 2026-07-24
```

日期必须是已有数据的交易日。命令会逐项打印接口状态，并把完整报告写到：

```text
reports/futures/audit/YYYY-MM-DD/audit.json
reports/futures/audit/YYYY-MM-DD/audit.md
```

命令退出码含义：

- `0`：阶段 1 数据底座所需的关键数据可用；
- `1`：至少一个关键市场或关键接口不可用。

控制台和报告会另外显示“阶段 3 回测内核就绪”状态。即使命令退出码为 `0`，只要
该状态为 `False`，就不能据此开展可信的期货回测。

主力映射返回 202 行。表中的合约资料包含历史合约，因此行数不能直接等同于当日在市
合约数；审计报告还会单独计算在市合约、品种覆盖和流动性候选。

## 4. 审计检查内容

审计会检查：

- 接口是否可调用、是否返回数据以及必需字段是否齐全；
- 指定日期的在市合约、日线合约和结算参数覆盖；
- 合约乘数或交易单位、交易时段是否缺失；
- 当日成交量和持仓量达到最低门槛的候选品种；
- 主力映射是否可用；
- 错误信息是否经过凭据脱敏。

审计只回答“数据能否支撑后续建设”，不选择策略，也不证明策略有效。

## 5. 已知缺口和处理原则

当前数据网关对 `ft_limit` 返回“接口名不正确”。结算接口已经提供保证金比例，但不能
替代涨跌停价。阶段 3 前需要选择并验证以下方案之一：

1. 数据供应商补充兼容官方 `ft_limit`；
2. 从各交易所公开数据建立统一的历史涨跌停数据集；
3. 接入另一个可提供历史涨跌停价的数据源。

不能用固定百分比或当前交易规则反推全部历史涨跌停价，这会遗漏规则调整和特殊交易日，
并造成不可成交场景被错误成交。
