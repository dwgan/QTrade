# 期货阶段 6：前瞻影子观察

## 1. 阶段边界

阶段 6 的工程入口已经实现，但真实观察期尚未开始，更没有完成。冻结协议的 forward 分区从
2026-08-03 开始，验收要求连续积累 8～12 周真实盘后记录。当前日期为 2026-08-01，且正式
signal 链和 `futures_limits` 仍缺失，因此不能用历史回填、合成行情或测试夹具冒充前瞻观察。

工程验收与运行验收严格分开：

- 工程验收：能够把冻结 signal 与次日精确日期的真实行情、结算、涨跌停和合约规则绑定为
  内容寻址的不可变观察；
- 运行验收：从 forward 起点连续运行至少 8 周，逐日记录数据故障、理论成交、换月、费用和
  保证金偏差，期间不修改冻结策略；
- 只有运行验收结束后，才允许评估是否继续研究或连接期货公司接口。

本阶段没有扩大产品范围：仍不连接券商、不下单、不接收账户成交回报。

## 2. 日度流程

每个交易日 `T` 收盘且供应商分区完成归档后：

1. 更新 `T` 日标准期货数据并通过质量门禁；
2. 以截至 `T` 的不可变阶段 2 构建生成 signal，`eligible_date` 必须为 `T+1`；
3. signal 必须使用正式冻结协议的 `config_hash`，并通过自身 `targets.parquet` SHA256 校验；
4. `T+1` 收盘并归档实际合约日线、结算参数和涨跌停后，运行影子观察；
5. 保存每条目标变化或换月腿的理论成交结果，阻断订单不得改写为成交；
6. 同一输入重复运行复用原构建，任何输入修订产生新构建并保留旧版本。

观察输入示例：

```json
{
  "protocol_path": "../config/futures_trend_v1.yaml",
  "signal_build_id": "<T日不可变signal构建ID>",
  "observation_date": "2026-08-04"
}
```

执行：

```powershell
.\.venv\Scripts\python.exe -m qtrade futures shadow-observe `
  --input runtime/futures-shadow.json
```

## 3. 可成交性与偏差记录

`FuturesShadowObservationService` 使用与阶段 3 相同的保守日线执行器：

- 买入按开盘价上加一个最小跳动，卖出按开盘价下减一个最小跳动；
- 缺开盘、无成交、日内区间异常、缺涨跌停、锁在不利方向涨跌停或保证金不足均明确阻断；
- 同合约目标变化记录开仓或减仓腿；反向先平后开；
- 合约变化记录 `roll_close` 和 `roll_open` 两条腿，旧腿阻断时新腿不尝试；
- 手续费从 `T+1` 结算参数推导，只标为理论费用；
- 观察保证金按 `T+1` 结算价、乘数、方向保证金率和目标整手手数计算，并与 signal 在 `T`
  估计的初始保证金比较；
- 输出 `fully_executable`、阻断腿数、理论费用、观察保证金、压力保证金和保证金偏差；
- 不输出 `total_return`、Sharpe 或策略有效性判断。

日线数据不能证明夜盘内的真实成交路径，系统固定记录
`night_session_status=not_observable_from_daily_data`。未连接券商时，真实成交与真实手续费固定记录
为 `not_connected` / `broker_actual_unavailable`，不能用理论值填入“实际”字段。

## 4. 不可变产物与谱系

产物位置：

```text
data/curated/futures/shadow-observations/build_id=<内容哈希>/
├── manifest.json
└── executions.parquet

reports/futures/shadow-observations/<观察日期>/<构建ID>/report.md
```

构建 ID 绑定：

- 冻结协议文件及 `content_hash`；
- 当前 signal manifest 和目标文件；
- 上一 signal manifest 和目标文件（若存在）；
- signal 声明的时点合约主数据；
- `T+1` 的日线、结算和涨跌停分区；
- 观察请求内容。

所有输入和输出均记录大小与 SHA256。当前 signal 必须位于 forward 分区，必须与正式协议的
`config_hash` 一致；上一 signal 必须使用相同策略参数和研究构建，且生效日等于当前信号日。
这些门禁防止在观察期根据短期表现替换参数、研究序列或历史目标。
manifest 另记录 UTC `recorded_at`，可区分市场日期与系统实际生成观察的时间点。
