# 期货阶段 5：只读操作界面

## 1. 完成范围

阶段 5 在原 A 股工作台中增加“市场切换 + 期货专属工作区”。两个市场共享本地
`ThreadingHTTPServer` 和基础视觉系统，但拥有独立页面层级、状态和数据接口。期货工作区只读，
不连接券商、不保存用户交易指令，也没有下单、撤单或修改研究产物的接口。

页面覆盖：

- 最新正式 signal、信号日、可执行日、协议和研究构建；
- 品种方向、实际目标合约、整手手数、初始保证金和压力保证金；
- 回测账本中的当前实际合约持仓；
- 连续研究序列、冻结输入中的实际合约行情和换月标记；
- 最新回测的收益、回撤、执行问题和质量门禁；
- 数据覆盖、验证就绪状态和明确阻断原因。

桌面端使用双栏总览和完整工作区，移动端将内容折叠为单栏；宽表仅在表格容器内部滚动，
不会造成页面级横向溢出。

## 2. 只读 API

| 方法与路径 | 内容 | 关键参数 |
| --- | --- | --- |
| `GET /api/futures/meta` | 可展示的 signal、回测和研究构建索引 | 无 |
| `GET /api/futures/overview` | 最新或指定 signal 的总览、目标、持仓和质量 | 可选 `id` |
| `GET /api/futures/chart` | 连续序列、实际合约行情和换月 | 必填 `product`，可选 `id` |
| `GET /api/futures/backtest` | 最新或指定回测的指标、账本和问题 | 可选 `id` |

构建 ID 和品种代码均使用白名单格式校验。期货 API 错误返回稳定的 `code` 和 `message`；
异常文本中的 Windows 绝对路径会被替换，浏览器不会获得本地数据目录。服务没有任何
`POST`、`PUT` 或 `DELETE /api/futures/*` 路由。

## 3. 数据谱系与完整性边界

`FuturesUiRepository` 是只读投影层，不计算策略信号，也不重跑回测：

1. 只枚举 `passed=true` 的不可变构建 manifest；
2. signal 的 `targets.parquet` 必须与 manifest 中唯一 `output_versions` 记录的大小和 SHA256
   完全一致；
3. 连续序列和换月表同样在读取前核验 `output_versions`；
4. 实际合约图表只读取该研究构建 `inputs` 中冻结的 `futures_daily` 文件，并再次核验大小和
   SHA256，不会扫描或拼接研究结束后新增的数据；
5. 回测的账户、持仓、成交和问题文件必须全部具有内容版本声明并通过核验。阶段 3 写入器已
   补充这些 `output_versions`，旧的无版本回测产物不会被当作正式 UI 结果；
6. 缺少 signal 时返回零目标、零持仓的明确空状态；缺文件或哈希不匹配时阻断请求，不用默认值
   制造收益、信号、持仓或质量结论。

前端只负责格式化上述结构化值。图表价格来自连续研究产物或实际合约冻结输入；空数组显示空
状态，不做插值或合成。

## 4. 当前真实数据阻断

截至 2026-08-01，真实就绪审计仍为 `ready=false`：

- `futures_daily` 历史覆盖不足；
- `futures_settlements` 仅有很短覆盖；
- `futures_limits` 缺失；
- development 分区的正式 signal 链缺失。

因此真实界面显示“无正式信号”和“存在阻断”，不展示正式收益。阶段 5 完成仅代表只读界面、
谱系校验和空状态已可用，不代表阶段 4 协议通过真实历史验证。
