# 期货阶段 1 数据底座

## 1. 当前状态

阶段 1 的工程能力已经完成：

- 建立独立于股票数据的期货 Dataset 和 Schema；
- 保存原始层与标准层 Parquet 分区；
- 支持指定交易日增量更新和日期区间回填；
- 支持按真实合约代码批量回填历史日线；
- 保存合约规则观测版本及内容哈希；
- 生成清单和独立的期货数据质量报告；
- 对可选接口不可用、字段缺失和数据异常分级处理。

真实数据验收仍存在两个外部数据缺口：

- 当前网关不支持 `ft_limit`，历史涨跌停价未落盘；
- 2026-07-24 的结算记录中有 68 行缺少正数保证金比例。

因此，数据底座可以用于阶段 2 的连续序列和动态品种池开发，但尚不能进入依赖完整
保证金与涨跌停成交约束的阶段 3 回测验收。

## 2. 标准数据集

| 数据集 | 内容 | 分区主键 |
| --- | --- | --- |
| `futures_contracts` | 合约资料完整观测快照 | `ts_code, observed_at` |
| `futures_contract_rules` | 交易单位、乘数、到期和时段的哈希版本 | `ts_code, observed_at` |
| `futures_daily` | 真实合约日线、结算价、成交量和持仓量 | `ts_code, trade_date` |
| `futures_settlements` | 手续费和多空保证金比例 | `ts_code, trade_date` |
| `futures_mappings` | 供应商主力合约映射 | `ts_code, trade_date` |
| `futures_limits` | 涨跌停价和保证金比例 | `ts_code, trade_date` |
| `futures_calendar` | 六市场交易日历 | `exchange, cal_date` |

数据路径示例：

```text
data/raw/futures/futures_daily/provider=tushare/as_of_date=2026-07-24/
data/curated/futures/futures_daily/provider=tushare/as_of_date=2026-07-24/
```

每个分区包含 `data.parquet` 和 `metadata.json`。元数据记录数据源、抓取时间、行数、
字段和请求范围，不保存 Token。

## 3. 日常更新

查看支持的数据集：

```powershell
.\.venv\Scripts\python.exe -m qtrade futures datasets
```

更新一个交易日的全部期货数据：

```powershell
.\.venv\Scripts\python.exe -m qtrade futures update --date 2026-07-24
```

只更新部分数据：

```powershell
.\.venv\Scripts\python.exe -m qtrade futures update `
  --date 2026-07-24 `
  --datasets futures_daily,futures_settlements,futures_mappings
```

`futures_limits` 当前被标记为可选数据：供应商不支持时会显示 `UNAVAILABLE`，并写入
报告，但不会让其他数据回滚或消失。其他关键数据下载或校验失败时命令返回非零退出码。

## 4. 历史回填

按交易日回填：

```powershell
.\.venv\Scripts\python.exe -m qtrade futures backfill `
  --start 2026-07-01 `
  --end 2026-07-24
```

已经完整存在的分区会跳过。默认回填日线、结算、主力映射和涨跌停；也可以通过
`--datasets` 缩小范围。

按真实合约回填日线：

```powershell
.\.venv\Scripts\python.exe -m qtrade futures contract-backfill `
  --ts-code CU2608.SHF `
  --start 2026-01-01 `
  --end 2026-07-24
```

供应商返回的区间数据会按交易日拆分，并与已有全市场分区合并后按主键去重，不会覆盖
同一天其他合约。

## 5. 质量与版本规则

质量报告位置：

```text
reports/futures/data-quality/YYYY-MM-DD/report.json
reports/futures/data-quality/YYYY-MM-DD/report.md
reports/futures/manifests/YYYY-MM-DD/manifest.json
```

校验包括：

- 必需字段、空主键和重复主键；
- 交易日期是否与分区一致；
- 日线价格关系、结算价、成交量和持仓量；
- 多空保证金比例；
- 涨跌停上下界；
- 可选数据源不可用状态。

无有效开高低价但存在结算价的记录会保留并告警。这类记录可以用于结算和持仓研究，
不能用于成交价模拟。缺少保证金比例的记录同样保留，但不得进入保证金感知回测。

合约规则版本使用 `observed_at`，含义是“系统实际在哪一天抓取并观察到这套规则”，不能使用
命令中的历史行情日期代替。它不宣称当前供应商返回的规则从某个历史日期起生效，避免用今天
看到的规则倒填历史。阶段 2 还会同时核对分区元数据中的 `fetched_at`，防止旧数据中的错误标签
绕过时点门禁。

## 6. 真实验证

2026-07-24 的完整更新成功退出：

| 数据集 | 行数 |
| --- | ---: |
| 合约资料 | 11127 |
| 合约规则版本 | 11127 |
| 日线 | 1073 |
| 结算参数 | 912 |
| 主力映射 | 202 |
| 六市场日历 | 6 |

质量报告记录了 103 行缺少有效日内 OHLC、68 行缺少完整保证金比例，以及
`futures_limits` 接口不可用。真实执行 `CU2608.SHF` 单合约回填后，全市场分区仍保持
1073 个唯一主键，合并保护有效。

2026-08-01 再次以 2020-12-31 验证历史深度，取得 815 行日线和 240 行结算参数，
质量门禁通过。供应商对 2 个零成交合约未返回持仓量；系统保留原始空值并记录
`missing_inactive_open_interest` 警告，不将其填零，也不允许这些记录进入可交易品种池。
当前自建网关仍未实现 `ft_limit`；同日验证官方接口所需的独立有效凭证也未配置，因此
历史涨跌停分区继续保持缺失，正式回测和 signal 链仍按设计阻断。

随后确认该供应商的 SDK/HTTP 路由虽然拒绝 `ft_limit`，但其文档提供的 MCP
`query_data` 工具可以返回该接口。系统支持通过仅存在于运行环境的
`TUSHARE_MCP_URL` 为 `ft_limit` 启用分页 fallback；MCP URL 及其中的凭证不会写入仓库。
fallback 对供应商报告总数执行完整性校验，空页、重复页、语义错误、HTTP 超时或最终行数
不足都会失败，不允许把前 50/200 行误记为完整分区；临时失败按供应商重试配置处理。
为避免大结果集在较高 offset 触发供应商 `context cancelled`，单日涨跌停按交易所分别查询、
逐页顺序获取并在页间限速，最后再合并执行全市场唯一键校验。专门回填可选数据集时，
`unavailable` 会记为失败并立即停止，不会在供应商冷却期间把缺失日期误计为完成或继续轰炸。

2026-08-01 通过该通道重新归档 2020-12-31，共取得 662 行、662 个唯一合约主键，
`up_limit/down_limit/m_ratio` 均为数值类型且上下界校验通过。分区额外记录
`source_transport=mcp_query_data` 和供应商报告总行数 662，内容 SHA256 为
`beb93d9f1e80807354a8edf7ce855634e05529870841ec5c260e8bb36b01bb36`。
这只证明单日链路完整；在 development 全区间回填完成前，正式验证仍保持阻断。
同样方式取得 2020-12-30 的 662 行数据，按交易所拆分后的冷启动耗时约 50 秒；
2020-12-28 至 2020-12-31 短区间回填结果为新增 2 天、跳过 2 天、失败 0，验证了断点续传。

## 7. 下一阶段入口

阶段 2 可以基于以下数据开展：

- `futures_contracts` 判断上市、到期和可交易区间；
- `futures_daily` 计算历史流动性和时点一致主力合约；
- `futures_mappings` 仅用于对照，不作为不可变换月表的唯一依据；
- `futures_contract_rules` 追踪后续规则观测变化。

进入阶段 3 前，必须补齐历史涨跌停价，并为目标品种补齐或建立可追溯的历史保证金规则。
