# 期货阶段 4：防作弊验证

## 1. 完成范围

阶段 4 工程实现已经完成，包括趋势目标、组合风控、日度快照链、多日回测输入编译、冻结
协议、稳健性场景、实验台账和封存门禁。真实历史收益仍未获准发布，因为本地数据没有通过
冻结 development 分区的就绪审计。

## 2. 冻结协议

正式协议位于 `config/futures_trend_v1.yaml`，使用通用 `StrategyProtocol` 模型并保存规范内容
SHA256。运行时通过 `ProtocolStore.install_frozen()` 安装；文件被修改或同 ID 内容不同均拒绝。

冻结分区：

| 分区 | 日期 | 规则 |
| --- | --- | --- |
| development | 2015-01-01 至 2020-12-31 | 可排错，不作为独立证据 |
| validation | 2021-01-01 至 2022-12-31 | 最多运行一次完整套件 |
| holdout | 2023-01-01 至 2024-12-31 | 显式一次性揭晓，禁止调参 |
| forward | 2026-08-03 起 | 每日观察，不用于历史调参 |

验证集和封存集还必须在协议冻结前绑定 64 位数据版本。当前协议保持 `unfrozen`，因此真实数据
补齐前无法运行这两个分区。补齐数据后应创建子协议版本并绑定数据版本，不能修改本协议。
编译 manifest 会对阶段 2、signal 链、实际合约行情、结算、涨跌停和合约主数据的内容哈希
生成独立 `data_version`；该版本不包含协议文件本身，因而可以先用父协议只编译不计算收益，
再写入子协议并冻结。正式运行会先编译、核验绑定版本，之后才允许计算任何验证收益。

## 3. 预注册场景

协议冻结七个场景：

1. `baseline`：基准 T+1 成交、基准成本和保证金；
2. `delayed_execution_1d`：额外延迟一个交易日；
3. `double_cost`：手续费加倍；
4. `margin_up_50pct`：多空保证金率均上调 50%；
5. `slower_roll`：换月确认增加一个交易日；
6. `faster_trend`：趋势周期乘 0.9，波动率窗口 30 日；
7. `slower_trend`：趋势周期乘 1.1，波动率窗口 50 日。

参数邻域必须使用按场景参数生成的独立 signal 链。换月邻域必须使用按对应确认天数生成的独立
阶段 2 构建。编译器会核验协议 ID 和研究配置，不能把基线产物换个场景标签重复使用。

## 4. 多日回测输入编译

`FuturesBacktestInputCompiler` 将 signal schema v3 链编译为阶段 3 JSON：

- signal 链必须逐日匹配冻结分区内全部已归档行情日期；
- 每个 signal、阶段 2 产物和合约主数据均核验文件大小与 SHA256；
- 目标合约固定为信号日已决定的 `T+1` 实际合约；
- 延迟场景只推迟成交生效日，不允许改用延迟日事后主力；
- 从逐日标准化分区读取实际合约 OHLC、成交量、结算、涨跌停和多空保证金；
- 从冻结合约主数据读取乘数和最小变动价位；
- 手续费使用信号日已归档规则，场景只能按冻结倍率调整；
- 换月旧腿和新腿分别使用各自手续费；
- 换月与手数变化同日发生时先完成等手换月，手数变化延后到下一快照；
- 缺少任何行情、结算、涨跌停、合约规则或链式谱系时不创建回测输入。

命令：

```powershell
qtrade futures compile-backtest --input runtime/futures-compile.json
```

不可变产物位于 `data/curated/futures/backtest-inputs/build_id=<id>/`。

## 5. 正式验证与实验台账

`FuturesStrategyValidationService` 依次编译并运行协议内全部场景，输出收益、年化收益、最大
回撤、追保天数和验收条件。每次套件运行写入通用 `ExperimentStore`；失败也永久保留并计入
validation 的一次试验上限。

冻结验收要求基线、成本加倍、延迟成交、换月变体和保证金变体满足预设最低年化收益，
保证金压力场景不得出现追保天数，两个参数邻域均须保持正向，且基线最大回撤不得超过 30%。

```powershell
qtrade futures validate-strategy --input runtime/futures-validation.json
```

正式运行要求：

- 研究代码工作树干净；
- 趋势策略实现提交与协议冻结提交一致；
- 协议哈希、策略参数 ID、分区和数据版本一致；
- holdout 首次运行必须显式 `reveal_holdout=true`；
- 任一场景的数据门禁或阶段 3 质量门禁失败时，整套实验失败并留痕。

## 6. 真实就绪验收

执行：

```powershell
qtrade futures validation-readiness `
  --protocol config/futures_trend_v1.yaml `
  --partition development
```

2026-08-01 本地真实数据结果为 `ready=false`，共四项错误：

- `futures_daily` 仅覆盖 2026-07-01 至 2026-07-31；
- `futures_settlements` 仅覆盖 2026-07-24；
- `futures_limits` 没有任何分区；
- 没有覆盖 development 的正式 signal 链。

审计报告位于 `reports/futures/validation-readiness/`。这些是安全阻断，不是可以用默认涨跌停、
当前保证金或合成数据绕过的问题。因此阶段 4 工程完成，但当前不发布任何真实策略收益，也不
揭晓 validation 或 holdout。
