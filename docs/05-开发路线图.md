# 开发路线图

## 1. 总体节奏

MVP 预计用 10 周完成。时间是规划基线，可以按个人可投入时间调整，但里程碑顺序不应倒置。

```text
数据基础
  → 市场分析
  → 行业分析
  → 多因子选股
  → 严谨回测
  → 自选股和观察组合
  → 本地看板
  → 真实盘后观察
```

## 2. 第 1～2 周：数据基础

### 目标

形成稳定、可增量更新的数据底座。

### 工作项

- 建立 Python 项目骨架
- 建立配置和日志系统
- 实现 Tushare 数据适配器
- 获取交易日历和证券基础信息
- 获取股票、指数日线数据
- 获取复权因子
- 获取股票状态和指数成分数据
- 建立 Parquet 分层存储
- 引入 DuckDB 查询
- 建立数据质量检查
- 建立命令行入口

### 交付物

- `qtrade data update`
- `qtrade data validate`
- 数据字典
- 一份指定日期的数据质量报告

### 完成标准

- 重复运行不会生成重复记录
- 中断后可以安全重跑
- 能明确识别缺失和延迟数据
- 原始数据和清洗数据可追溯

## 3. 第 3 周：市场分析 MVP

### 工作项

- 主要指数趋势
- 市场宽度
- 新高、新低统计
- 实现波动率和回撤指标
- 构建第一版市场温度
- 生成市场状态
- 输出每日 Markdown/HTML 报告

### 交付物

- `qtrade analyze market`
- 市场总览报告
- 市场模型单元测试

### 完成标准

- 任意历史交易日可重新生成分析
- 每个得分均能查看构成指标
- 数据不足时不输出伪精确评分

## 4. 第 4 周：行业和风格分析

### 工作项

- 接入行业分类及历史变更
- 计算行业多周期收益
- 计算行业相对强弱
- 计算行业内部扩散度
- 分析成交额和估值位置
- 构建风格相对强弱面板

### 交付物

- 行业排名表
- 行业状态标签
- 行业热力图
- 每周行业变化报告

## 5. 第 5～6 周：多因子选股

### 工作项

- 建立历史股票池
- 对齐财报公告日期
- 实现质量因子
- 实现价值因子
- 实现动量因子
- 实现低风险因子
- 去极值、标准化和中性化
- 实现综合评分
- 实现风险过滤
- 输出候选股票解释

### 交付物

- `qtrade analyze stocks`
- 因子快照
- 候选池
- 个股分析卡片

### 完成标准

- 不使用公告前财务数据
- 当前日期和历史日期使用相同处理逻辑
- 每个候选结果可解释、可追溯

## 6. 第 7～8 周：回测和稳健性

### 工作项

- 因子分组回测
- 候选组合回测
- 下一交易日成交模型
- 停牌和涨跌停处理
- 费用与滑点模型
- 样本内、验证和样本外划分
- Walk-forward 验证
- 参数敏感性测试
- 分行业、分年度归因

### 交付物

- `qtrade backtest run`
- 因子研究报告
- 组合回测报告
- 稳健性报告

### 完成标准

- 所有结果包含基准
- 交易成本加倍后结果已展示
- 样本外结果与样本内结果分开呈现
- 不隐藏表现较差的市场阶段

## 7. 第 9 周：自选股和观察组合

### 工作项

- 自选股配置
- 自选股每日评分
- 候选池进入/退出记录
- 受限等权观察组合
- 每周模拟调仓
- 历史信号不可变快照
- 周度复盘报告

### 交付物

- 自选股报告
- 观察组合净值
- 候选池变化记录
- 周度复盘报告

## 8. 第 10 周：本地看板

### 工作项

- Streamlit 本地界面
- 市场总览
- 行业热力图
- 候选股列表
- 个股详情
- 自选股页面
- 回测页面
- 数据质量状态

### 完成标准

- 看板只读取已经生成的结构化结果
- 看板故障不影响数据和报告任务
- 所有页面标明数据截止日期

## 9. MVP 后：真实盘后观察

持续 8 至 12 周：

- 每日盘后自动运行
- 保存当日市场状态和候选池
- 每周更新观察组合
- 记录数据故障和模型异常
- 比较模拟结果与回测预期
- 收集需要改进的解释和展示问题

观察结束后再决定是否：

- 调整因子和权重
- 增加高股息子策略
- 增加行业轮动
- 引入公告和事件数据
- 加入大语言模型生成自然语言摘要

## 10. 第一阶段实施清单

开始编码时按以下顺序：

1. 初始化 Python 包和测试框架。
2. 定义配置模型。
3. 定义交易日历、证券、行情等核心数据结构。
4. 实现数据源协议。
5. 实现 Tushare 适配器。
6. 实现原始数据保存。
7. 实现日线清洗和复权因子保存。
8. 实现数据质量检查。
9. 实现增量更新 CLI。
10. 为上述流程补充测试和使用说明。

在第一阶段完成前，不开始优化策略参数。
