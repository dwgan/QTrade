# 期货阶段 2 连续序列与动态品种池

## 1. 范围

阶段 2 只建设研究数据，不生成策略信号，不计算组合收益，也不模拟成交。

实现内容：

- 根据当时可见的成交量、持仓量、上市日和到期日选择实际合约；
- 保存决定日、下一交易日生效日、候选快照和输入哈希；
- 生成真实合约价格、连续收益指数和后复权研究价格；
- 生成按日动态品种池及排除原因；
- 将自建映射与供应商 `fut_mapping` 对照；
- 对重复日期、缺失换月价格、异常跳点和未来日期执行质量检查；
- 按输入文件内容和配置生成不可变构建版本。

历史涨跌停价和部分保证金比例仍有缺口。它们不阻止本阶段，但继续阻止阶段 3
可信回测验收。

## 2. 主力合约规则

对每个品种和决定日 `T`：

1. 只使用 `T` 日及以前已经落盘的数据；
2. 合约快照的行观察日和元数据实际抓取日都不得晚于研究起始日；
3. 只考虑已上市、结算价有效且距离到期超过安全缓冲的合约；
4. 初始合约按持仓量、成交量和到期日排序选择；
5. 只有更晚到期合约的持仓量连续两个决定日高于当前合约，才常规换月；
6. 当前合约不再满足到期安全约束或行情缺失时强制换月；
7. `T` 日决定的合约从下一可用交易日 `T+1` 生效；
8. 候选合约、成交量、持仓量、到期日和候选快照哈希写入换月表。

默认参数在 `config/base.yaml` 的 `futures` 节中配置。修改参数会产生不同的构建 ID，
不会覆盖既有结果。

## 3. 连续序列

每个生效日同时保存：

- `contract_code`：当日对应的真实合约；
- `actual_open/high/low/close/settle`：真实合约未调整价格；
- `continuous_return`：同一实际合约相邻结算价收益；
- `continuous_index`：从 1.0 开始串接的连续收益指数；
- `research_price`：从首日真实结算价开始串接的后复权研究价格；
- `adjustment_factor`：研究价格与当日真实结算价之比；
- `decision_date`、换月标志和换月原因。

换月日收益使用新合约在换月前一交易日到生效日的自身收益，不把旧合约与新合约的绝对价差
误记为收益。研究价格只能用于信号和波动率计算，禁止用于实际成交或逐日盈亏。

## 4. 动态品种池

品种池按每个交易日独立计算，不使用期末活跃品种列表回填历史。默认检查：

- 可见历史天数；
- 满足到期安全约束的合约数量；
- 回看窗口内平均成交量、持仓量和成交金额；
- 合约乘数和交易时段是否完整。

输出保留全部已观察品种。被排除的品种不会从历史数据中删除，而是记录
`status=excluded` 和分号分隔的 `exclusion_reasons`。

## 5. 使用方法

先准备至少两个交易日的标准日线与供应商映射：

```powershell
.\.venv\Scripts\python.exe -m qtrade futures backfill `
  --start 2026-07-01 `
  --end 2026-07-24 `
  --datasets futures_daily,futures_mappings
```

再执行纯离线构建：

```powershell
.\.venv\Scripts\python.exe -m qtrade futures build-series `
  --start 2026-07-01 `
  --end 2026-07-24
```

构建命令不访问供应商，也不读取 Token。只有回填命令从 Windows 用户环境变量读取数据源配置。

## 6. 输出与不可变性

标准研究产物写入：

```text
data/curated/futures/research/build_id=<内容哈希>/
  manifest.json
  roll_schedule.parquet
  continuous.parquet
  universe.parquet
  vendor_comparison.parquet
```

质量报告写入：

```text
reports/futures/continuous/<结束日期>/<构建ID>/report.json
reports/futures/continuous/<结束日期>/<构建ID>/report.md
```

构建 ID 包含日期范围、阶段 2 配置、所有输入 Parquet 文件以及合约快照元数据的 SHA-256。
清单分别记录合约分区日期和经元数据校验后的实际观察日。相同输入重复运行只读取既有不可变
版本；任何输入或参数变化都会创建新版本。供应商映射只记录匹配率和差异，不能替代自建换月表。

## 7. 质量门禁

以下问题标记为错误并令命令返回非零退出码：

- 同一品种同一日期出现重复换月、连续序列或品种池记录；
- 输入日线出现重复的实际合约与交易日主键；
- 决定日不早于生效日；
- 已选择合约在生效日缺少行情；
- 换月时缺少新合约上一交易日结算价。

连续单日收益绝对值超过配置阈值时标记警告，保留数据供人工审查。供应商映射不一致单独保存，
不自动判定自建映射错误。

## 8. 真实数据验证

使用实际抓取于 `2026-07-30` 的合约快照和 `2026-07-30` 至 `2026-07-31` 的真实日线构建：

- 构建 ID：`f853ddfc1e5094a151ea`；
- 换月表与连续序列：各 87 行；
- 动态品种池：174 行；
- 供应商映射对照：87 行，其中 79 行一致，匹配率 90.80%；
- 质量错误与警告：0。

该窗口只有两个交易日，用于验证真实数据落盘、观察时间门禁、连续序列生成、供应商对照和
不可变产物。窗口内没有实际换月，且不足 20 日流动性门槛；两日确认换月、换月收益串接、
动态准入和未来数据拒绝由手工可核对的自动化夹具覆盖。不能据此进入策略或回测阶段，阶段 3
仍受历史涨跌停价和保证金缺口阻断。
